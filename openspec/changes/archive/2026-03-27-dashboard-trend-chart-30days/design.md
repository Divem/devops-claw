## Context

当前 Admin Dashboard 的创建趋势图表使用简单的 CSS 条形图实现，仅支持显示最近 7 天的静态数据。随着平台规模扩大，管理员需要更灵活的数据分析能力，包括：

- 查看更长时间跨度的趋势（30天、90天）
- 平滑浏览历史数据（左右滚动）
- 快速切换不同时间范围

现有实现位于 `/src/views/admin/AdminDashboard.vue`，使用纯 CSS 实现条形图，数据通过 `/api/admin/dashboard` 接口获取。

## Goals / Non-Goals

**Goals:**
- 将趋势图表升级为可交互的线图/面积图，支持手势滚动和缩放
- 默认显示近 30 天数据（可配置）
- 提供时间范围筛选器，支持 7天/30天/90天/自定义 快速切换
- 保持现有 API 兼容性，平滑升级用户体验
- 确保 30 天数据渲染性能良好（<100ms 首屏渲染）

**Non-Goals:**
- 后端 API 改动（保持现有 `/api/admin/dashboard` 接口）
- 数据导出功能
- 图表类型切换（线图/柱状图/饼图）
- 实时数据更新（WebSocket）
- 移动端触摸手势优化（二期迭代）

## Decisions

### 1. 图表库选择：ECharts
**决定**：引入 ECharts 作为图表库
**理由**：
- 功能完善，支持缩放、滚动、提示框等交互特性
- 中文文档完善，社区活跃
- 与 Vue 3 集成良好（vue-echarts）
- 相比 Chart.js 更适合时序数据展示
**备选**：Chart.js（更轻量，但交互特性需额外插件）

### 2. 交互模式：DataZoom 组件
**决定**：使用 ECharts 内置的 `dataZoom` 组件实现滚动
**理由**：
- 原生支持鼠标拖拽、滚轮缩放
- 可配置缩放范围（如显示最近 7 天，但可滚动查看 30 天）
- 无需额外实现虚拟滚动逻辑
**备选**：自定义滚动条（开发成本高，性能优化复杂）

### 3. 时间范围数据策略：前端筛选
**决定**：前端一次性获取 90 天数据，按时间范围筛选显示
**理由**：
- 90 天数据量可控（约几百条记录）
- 避免频繁 API 调用，提升交互响应速度
- 筛选操作零延迟
**风险**：若数据量增长需改为后端分页

### 4. 组件拆分：独立趋势图组件
**决定**：提取 `InteractiveTrendChart` 独立组件
**理由**：
- 逻辑与视图分离，便于测试和复用
- 避免 AdminDashboard.vue 过于臃肿
- 支持未来在其他页面复用
**文件位置**：`/src/components/dashboard/InteractiveTrendChart.vue`

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| ECharts 包体积增加 (~200KB gzipped) | 首屏加载时间 | 按需引入组件，配合 Vite 代码分割 |
| 30 天数据渲染性能 | 低端设备卡顿 | 启用 ECharts 节流，限制同时渲染点数 |
| 用户学习成本 | 操作困惑 | 添加引导提示，保持默认行为与旧版一致 |
| 自定义日期范围校验 | 无效日期输入 | 使用 Naive UI DatePicker，内置校验 |

## Migration Plan

**部署步骤**：
1. 开发阶段：在 feature 分支开发，保持旧版组件并存
2. 测试阶段：QA 验证交互功能，性能基准测试
3. 灰度阶段：AB 测试，观察用户反馈
4. 全量发布：移除旧版代码，清理无用样式

**回滚策略**：
- 保留旧版趋势图代码 1 个版本
- 通过 feature flag 快速切换
- 若出现严重问题，30 分钟内可回滚

## Open Questions

1. **数据量上限**：当前假设 90 天数据可前端处理，若实例数增长 10 倍是否需要后端分页？
2. **自定义日期范围**：是否需要限制最大跨度（如最多 90 天）？
3. **图表类型**：是否需要支持用户切换线图/柱状图？
4. **导出功能**：二期是否需要支持图表导出为图片？
