## Context

当前机器人信息面板采用单字段编辑模式，用户需要分别点击编辑 AppID 和 secret，体验不够流畅。本设计旨在实现批量编辑模式，允许用户在一个表单中同时修改这两个关联凭证。

**当前架构：**
- 前端：Vue 3 + TypeScript + Naive UI
- 状态管理：Pinia stores
- API：RESTful 接口
- 机器人配置存储在项目中，通过 BotConfigPanel 组件展示

## Goals / Non-Goals

**Goals:**
- 实现 AppID 和 secret 的批量编辑功能
- 提供统一的表单验证和错误提示
- 确保数据更新的原子性
- 保持向后兼容，不影响现有 API

**Non-Goals:**
- 不修改数据库存储结构
- 不引入新的第三方依赖
- 不涉及其他凭证字段的批量编辑

## Decisions

### 1. 表单设计方案
**选择**：使用单一表单同时展示 AppID 和 secret 输入框，提供「编辑」和「保存」按钮
**理由**：
- 符合用户心智模型，两个字段经常一起修改
- 减少用户操作步骤
- 代码实现简单，利用现有表单组件

**备选方案**：保持独立编辑，添加「批量编辑模式」开关
- 被拒绝：增加复杂度，实际收益有限

### 2. 验证策略
**选择**：前端实时验证 + 提交时统一校验
**理由**：
- AppID 和 secret 格式有关联性（通常成对出现）
- 统一校验可避免部分更新导致的不一致
- 减少 API 调用次数

### 3. API 设计
**选择**：复用现有更新接口，通过请求体同时传递两个字段
**理由**：
- 保持 API 向后兼容
- 无需新增接口
- 现有接口已支持批量字段更新

### 4. 错误处理
**选择**：字段级错误展示 + 全局提示
**理由**：
- 用户可以快速定位问题字段
- 全局提示提供操作反馈

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 用户误操作同时修改两个字段 | 添加确认弹窗，显示变更摘要 |
| 部分验证失败导致困惑 | 清晰的字段级错误提示，高亮问题字段 |
| 与现有单字段编辑模式冲突 | 新功能作为默认模式，移除旧模式代码 |
