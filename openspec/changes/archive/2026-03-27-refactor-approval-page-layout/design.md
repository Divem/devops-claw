## Context

当前审批管理页面 (`/admin/approvals`) 使用垂直卡片列表展示审批记录。每个卡片包含完整的审批信息，这在小数据量时工作良好，但当待审批记录增多时，会出现以下问题：

1. **视觉干扰**：每条待审批卡片都包含一个 `ApprovalGuide` 组件，展示相同的配置引导信息，造成页面冗余
2. **操作不便**："去配置"链接固定指向飞书开放平台首页，而非具体应用的配置页面，用户需要手动导航
3. **信息密度低**：当前卡片设计（较大的 padding、字体和间距）在单屏内只能显示少量记录，频繁滚动影响效率

## Goals / Non-Goals

**Goals:**
- 将配置引导从卡片中移除，整合为页面顶部的统一引导区域
- 实现动态配置链接，可直接跳转至对应应用的设置页面
- 提供紧凑视图和列表视图，提高单屏信息密度至少 50%
- 保持所有核心功能（审批、状态显示、时间展示）完整可用

**Non-Goals:**
- 不改变审批业务逻辑或数据模型
- 不添加新的审批功能（如批量审批、筛选等）
- 不修改飞书长连接的配置流程本身

## Decisions

### 1. 配置引导位置：页面顶部统一展示

**选择**：将配置引导从每张卡片移至页面顶部的 alert/info 区域

**理由**：
- 配置引导是通用信息，与具体审批记录无关，重复显示造成视觉干扰
- 页面顶部位置明显，管理员进入页面即可看到
- 与 naïve-ui 的 `n-alert` 组件配合良好，支持可关闭/折叠

**替代方案**：右侧边栏固定 - 否决原因：在小屏幕上会挤压主内容区

### 2. 视图模式：卡片视图 + 列表视图双模式

**选择**：保留优化后的卡片视图，新增列表视图作为备选

**理由**：
- 卡片视图适合详细查看单条记录（头像、时间等视觉元素完整）
- 列表视图适合快速浏览大量记录，行高控制在 56px 以内
- 提供视图切换按钮，让用户根据场景选择
- 视图偏好使用 localStorage 持久化

**替代方案**：仅优化卡片视图 - 否决原因：无法满足不同使用场景

### 3. 紧凑卡片设计

**选择**：
- 减小头像尺寸（32px → 24px）
- 减少卡片内边距（medium → small，或自定义 padding）
- 压缩行间距（16px → 8-12px）
- 水平排列部分信息以节省垂直空间

**理由**：
- 审批信息相对固定且可预测，不需要过多留白强调
- 紧凑设计可在 1080p 屏幕显示 6-8 条记录（原为 3-4 条）

### 4. 动态配置链接

**选择**：使用审批数据中的 `appId` 动态构建链接 `https://open.feishu.cn/app/{appId}/baseinfo`

**理由**：
- 用户可直接进入具体应用的设置页面，无需手动搜索
- 链接格式符合飞书开放平台标准
- 需要确认 `appId` 字段在 `Approval` 类型中已存在

## Risks / Trade-offs

**[Risk] 用户可能不习惯新的紧凑布局** → 提供视图切换功能，保留选择自由；设置合理的默认视图

**[Risk] 配置链接格式可能因飞书平台更新而失效** → 使用配置项或环境变量管理基础 URL，便于后续调整

**[Risk] 列表视图在小屏幕上显示效果不佳** → 在小屏幕（<768px）自动切换回卡片视图，确保移动端体验

**[Trade-off] 紧凑布局可能降低可读性** → 通过色彩区分、图标辅助来保持信息层次；在列表视图中使用悬停效果展示更多详情

## Migration Plan

本变更无需数据迁移，为纯前端 UI 调整：

1. 开发阶段：在独立分支实现，保持现有功能完整
2. 测试阶段：验证所有审批操作（查看、通过、跳转配置）正常工作
3. 部署阶段：直接部署，用户刷新页面即可看到新布局
4. 回滚：如出现问题，可快速回退到上一版本

## Open Questions

1. **Approval 数据模型**：`appId` 字段是否已存在于 `Approval` 类型中？如需后端支持，是否需要新增接口？
2. **配置引导内容**：统一的配置引导需要哪些具体步骤说明？是否需要截图或链接到内部文档？
3. **默认视图**：新用户首次访问时，默认使用卡片视图还是列表视图？
