## Context

当前 DevOps OpenClaw 平台的管理员实例管理页面(InstanceList)已具备完整的实例列表展示功能，包括：
- 实例信息展示（名称、所属员工、虚拟机状态、飞书连接状态等）
- 实例操作功能（启动、停止、重启、删除）
- 筛选和排序功能
- 实例详情抽屉

实例数据模型中的 `Instance` 类型已包含 `projectId` 字段，用于关联 OpenClaw 项目。

现有的 OpenClaw 配置页面路由为 `/projects/:id/admin`，使用 `OpenClawAdmin.vue` 组件，提供：
- 控制台视图（iframe 加载 Gateway Dashboard）
- 代码模式（ConfigCodeMode）
- 终端视图（TerminalView）

## Goals / Non-Goals

**Goals:**
- 在实例表格的操作列添加「配置」按钮
- 点击后导航到对应实例的 OpenClaw 管理页面
- 复用现有的路由和组件，不创建新的页面
- 保持表格现有操作的完整性和可用性

**Non-Goals:**
- 不修改 OpenClaw 管理页面的功能
- 不添加新的 API 端点
- 不改变现有实例数据模型
- 不添加权限控制（复用现有权限逻辑）

## Decisions

### Decision 1: 在操作列添加配置按钮
**选择：** 在现有操作列（启动/停止/重启/更多）中添加「配置」按钮，位于按钮组最右侧。

**理由：**
- 与现有操作按钮保持一致的位置和样式
- 配置是实例管理的重要操作之一，适合放在操作列
- 不占用额外的列空间，保持表格简洁

**替代方案考虑：**
- 方案A：新增独立列 - 会占用更多横向空间，且配置不是高频操作
- 方案B：放入「更多」下拉菜单 - 增加了操作步骤，降低了可发现性

### Decision 2: 通过事件传递 projectId 进行路由跳转
**选择：** InstanceTable 组件 emit `config` 事件，携带实例的 `projectId`，由父组件 InstanceList 处理路由跳转。

**理由：**
- 保持组件职责分离：Table 负责展示，父组件负责导航逻辑
- 复用现有的 Vue Router 实例
- 易于测试和扩展

### Decision 3: 使用 Vue Router 的 `push` 方法跳转
**选择：** 使用 `router.push(`/projects/${projectId}/admin`)` 进行编程式导航。

**理由：**
- 标准 Vue Router 用法，符合项目现有代码风格
- 保留浏览器历史记录，支持返回操作
- 不需要额外的依赖

## Risks / Trade-offs

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 操作列按钮过多导致拥挤 | 低 | 中 | 使用小尺寸按钮，合理间距；当前仅5个按钮，空间充足 |
| projectId 可能为空或无效 | 低 | 高 | 添加空值检查，仅在 projectId 存在时显示配置按钮 |
| 用户误点击配置按钮 | 低 | 低 | 配置是安全操作（仅跳转），不会导致数据变更 |

## Migration Plan

无需数据迁移或后端变更。部署步骤：
1. 合并代码变更
2. 构建并部署前端应用
3. 验证实例列表页面的配置按钮功能

回滚策略：
- 回滚前端构建版本即可
- 无数据或状态需要恢复
