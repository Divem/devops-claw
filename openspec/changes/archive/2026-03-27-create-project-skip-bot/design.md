## Context

当前 DevOps OpenClaw 平台的项目创建流程要求用户必须完成机器人配置才能继续。这增加了新用户的认知负担，延长了首次使用的时间。用户需要在不理解 OpenClaw 是什么的情况下就配置机器人，这不符合渐进式披露的用户体验原则。

## Goals / Non-Goals

**Goals:**
- 简化项目创建流程，允许用户先创建项目再配置机器人
- 默认选中第一个头像，减少用户选择负担
- 使 OpenClaw 卡片可点击，提供清晰的下一步指引
- 在飞书连接步骤提示用户之前跳过了机器人配置

**Non-Goals:**
- 完全移除机器人配置功能
- 修改项目创建的数据模型
- 改变飞书连接的逻辑

## Decisions

### 1. 使用可选步骤模式
**选择**: 将机器人配置从强制步骤改为可选步骤
**理由**: 
- 符合渐进式披露原则，让用户先体验核心功能
- 参考了 Notion、Figma 等产品的 onboarding 设计
- 减少首次使用的心理负担

### 2. 默认选中第一个头像
**选择**: 自动选择头像列表中的第一个
**理由**:
- 减少一个用户必须做的选择
- 如果用户不满意可以再更改
- 避免空状态导致的困惑

### 3. OpenClaw 卡片点击交互
**选择**: 点击 OpenClaw 卡片直接跳转到下一步
**理由**:
- 提供明确的行动召唤
- 减少用户的探索成本
- 与卡片式设计语言的交互模式保持一致

### 4. 后续配置提示位置
**选择**: 在【连接飞书】步骤后显示跳过提示
**理由**:
- 用户完成当前步骤后自然会看到提示
- 不干扰主要流程的进行
- 提醒用户有未完成的配置项

## Risks / Trade-offs

- **[Risk]** 用户可能忘记配置机器人导致功能受限 → **[Mitigation]** 在合适的时机（如需要使用机器人功能时）再次提醒
- **[Risk]** 默认头像可能不符合用户偏好 → **[Mitigation]** 头像选择明显且易于修改
- **[Trade-off]** 跳过了配置步骤可能导致后续需要中断流程来配置 → 在用户主动探索设置时提供入口
