## Context

当前实例管理页面 (`/admin/instances`) 仅支持查看、筛选和操作现有实例，管理员无法直接创建实例。现有流程要求用户通过飞书申请，管理员在审批面板中审批后才能创建，这对于需要快速为领导或特定人员配置实例的场景效率较低。

## Goals / Non-Goals

**Goals:**
- 在实例管理页面提供一键创建实例的入口
- 支持选择目标用户（员工/领导）和配置实例基本信息
- 创建成功后自动刷新列表并显示成功提示
- 复用现有审批创建的后端逻辑，保持一致性

**Non-Goals:**
- 复杂的实例配置（如自定义资源规格、网络配置等），保持简洁的创建流程
- 批量创建实例功能
- 实例模板功能

## Decisions

### 1. 使用弹窗而非抽屉
**选择**: 使用模态弹窗（Modal）而非侧边抽屉（Drawer）
**理由**: 
- 创建表单字段较少（实例名称、目标用户），弹窗足够容纳
- 与现有的「创建项目」等操作保持一致的交互模式
- 抽屉更适合展示详情，弹窗更适合表单操作

### 2. 用户选择组件
**选择**: 使用带搜索的下拉选择器（AutoComplete 或 Select）
**理由**:
- 企业员工数量可能较多，需要支持搜索筛选
- 显示用户名称和头像，便于识别
- 预留接口支持按部门筛选（未来扩展）

### 3. 后端 API 设计
**选择**: `POST /api/admin/instances`
**请求体**:
```json
{
  "name": "string",        // 实例名称，必填
  "ownerId": "string",     // 目标用户ID，必填
  "appId": "string"        // 可选，飞书应用ID
}
```
**理由**:
- 符合 RESTful 设计，管理员资源操作使用 `/api/admin/instances`
- 参数精简，必填项仅名称和目标用户，降低使用门槛

### 4. 错误处理策略
**选择**: 表单级错误提示 + Toast 全局提示
**理由**:
- 字段验证错误（如名称重复）显示在对应字段下方
- 服务端错误（如用户无权限）使用全局 Toast 提示
- 与现有项目创建的错误处理模式保持一致

## Risks / Trade-offs

**[风险] 误操作创建实例** → **缓解**: 添加确认对话框，显示创建摘要（实例名称、目标用户）

**[风险] 选择错误的目标用户** → **缓解**: 用户选择器显示头像和部门信息，提高识别度

**[风险] 与审批流程的实例冲突** → **缓解**: 实例名称唯一性校验复用现有逻辑

## Migration Plan

无需迁移，此功能为纯新增，不影响现有数据和流程。

部署步骤:
1. 部署后端 API 变更
2. 部署前端组件变更
3. 验证管理员可正常创建实例
