DevOps OpenClaw 产品需求文档

版本：v1.3 | 更新日期：2026-03-27

📋 文档说明

本文档详细描述了 DevOps OpenClaw 平台的产品需求，包含背景目标、用户角色、信息架构、核心流程、功能需求、技术规范等内容，用于指导产品开发和团队协作。

1. 产品关系说明

🌐

OpenClaw（开源项目）

开源个人 AI 助手平台，支持多聊天渠道接入、持久记忆、浏览器控制、系统访问、技能扩展

↓ 基于
📱

飞书 OpenClaw（飞书官方服务）

飞书基于 OpenClaw 封装的托管服务，一键云端部署，自动接入飞书，面向个人用户

↓ 模仿
🏢

DevOps OpenClaw（本项目）

企业内部自建的 OpenClaw 托管平台，面向公司全体员工，集中管理，数据自主可控

2. 背景与目标

2.1 背景

  • OpenClaw 是一个开源的个人 AI 助手平台，支持通过 WhatsApp、Telegram、Slack、飞书等聊天应用交互
  • 飞书 OpenClaw 是飞书官方基于 OpenClaw 封装的托管服务，用户点击即可一键云端部署
  • 公司使用飞书办公，飞书机器人由管理员统一创建和分配，员工无法自主创建机器人
  • 飞书 OpenClaw 面向个人用户，不满足企业集中管控需求
  • 员工若自行部署 OpenClaw，需要手动创建虚拟机、安装服务、配置飞书机器人对接，流程繁琐且容易出错

2.2 目标

本项目旨在模仿飞书 OpenClaw 的产品体验，搭建一个企业内部的 OpenClaw 托管平台：

目标描述
降低使用门槛模仿飞书 OpenClaw 的一键部署体验，员工无需关心底层基础设施
标准化部署统一部署模板和配置，确保每个实例的一致性和安全性
集中化管理管理员可统一监控和管理所有 OpenClaw 实例的生命周期
数据自主可控虚拟机部署在公司内部基础设施，数据不出企业边界
飞书深度集成通过飞书机器人 + WebSocket 长连接，实现与飞书的双向实时通信

3. 用户角色

角色描述核心诉求
员工普通企业用户像使用飞书 OpenClaw 一样，一键创建专属 AI 助手并通过飞书对话
管理员DevOps 平台管理员统一管理飞书机器人凭证、配置长连接、监控所有实例运行状态

5.2 员工创建流程

  1. 访问 DevOps OpenClaw 首页
  2. 点击「创建」按钮
  3. 弹窗：设置项目名
  4. 弹窗：配置飞书渠道 / 选择头像 / 可选填 AppID/AppSecret
  5. 创建进度展示（三步流程）
  6. 创建结果（成功/失败）
  7. 打开 OpenClaw 项目 / 查看审批单

5.3 管理员配置流程

  1. 收到飞书通知：新实例待配置长连接
  2. 登录 DevOps 管理后台
  3. 查看仪表盘 / 审批管理
  4. 查看待审批列表（卡片/列表视图）
  5. 确认员工信息、AppID、实例状态
  6. 前往飞书开放平台配置 WebSocket 长连接
  7. 返回管理后台，点击「通过审批」
  8. 系统验证长连接状态，通知员工

6. 员工端功能需求

6.1 P0 - 核心功能

功能描述
一键创建 OpenClaw填写项目名和飞书渠道信息，一键完成虚拟机创建、OpenClaw 安装和 Gateway 启动
创建进度实时展示分步骤展示创建进度（启动云端电脑 → 启动 OpenClaw → 连接飞书），每步含耗时；支持步骤点击跳转
项目状态展示项目卡片展示部署状态（创建中 / 已部署 / 审批中 / 异常），含操作按钮
项目配置管理三模式管理界面：控制台（iframe Gateway）、代码模式（文件编辑器）、终端（配置预览）
代码模式编辑基于 Monaco Editor 的配置文件编辑器，支持多标签、自动保存、文件树、搜索
终端模式查看终端风格界面展示系统信息和配置 YAML 预览
机器人信息管理下拉菜单展示 AppID/AppSecret，支持脱敏展示和快捷复制
删除项目二次确认后删除项目，释放虚拟机资源，数据不可恢复

6.2 功能规格详细说明

6.2.1 首页空状态引导

触发条件：

  • 用户首次登录系统
  • 用户删除了所有项目后返回首页
  • URL 路径为 / 且项目列表为空

用户场景：

  • 场景1 - 新员工首次登录：员工小王刚加入公司，首次登录系统，看到空状态引导页，了解产品功能后点击"立即部署"创建第一个项目
  • 场景2 - 删除所有项目后：员工小李删除了所有测试项目后返回首页，看到空状态提醒，决定重新创建正式项目

预期结果：

  • 页面显示友好的引导文案和插图
  • 明确告知用户下一步操作（点击"立即部署"）
  • 展示产品核心卖点，建立信任

约束条件：

  • 项目列表查询需在 500ms 内完成
  • 空状态需友好的视觉设计，避免用户困惑
  • 必须提供明确的操作入口
异常场景现象处理方式
项目列表加载失败空状态无法展示或持续显示加载中显示"数据加载失败"提示，提供"刷新"按钮，5秒后自动重试一次
网络断开用户处于离线状态显示离线提示，建议检查网络连接，不显示创建按钮避免用户误操作
数据权限异常用户无法获取自己的项目列表显示权限错误页，引导联系管理员，记录安全审计日志

6.2.2 项目列表展示

触发条件：

  • 用户已创建至少一个项目
  • 用户从其他页面返回首页
  • URL 路径为 / 且项目列表不为空

用户场景：

  • 场景1 - 查看所有项目：员工小张管理3个OpenClaw项目，需要快速查看各项目运行状态
  • 场景2 - 切换项目配置：员工需要切换到另一个项目的配置页进行对比
  • 场景3 - 清理过期项目：员工识别出审批中的项目已废弃，点击删除按钮进行清理

交互跳转说明：

  1. 页面加载时调用 /api/projects 接口
  2. 按创建时间倒序排列项目卡片
  3. 每个卡片展示：头像、项目名称、状态标签
  4. 提供操作按钮：配置 OpenClaw、机器人信息、删除

预期结果：

  • 以卡片网格形式展示所有项目
  • 状态标签实时反映项目状态（创建中/已部署/审批中/异常）
  • 点击"配置 OpenClaw"跳转至项目配置管理页

约束条件：

  • 最多展示 12 个项目，超出需分页
  • 状态更新需要实时或准实时（轮询 30s）
  • 项目名称最长 50 字符，超出显示省略号
异常场景现象处理方式
状态数据过期卡片显示"已部署"但实际服务已停止增加状态检查提示，点击状态标签可触发手动刷新
项目名称过长项目名超过50字符显示异常自动截断并显示省略号，悬停显示完整名称
批量操作卡顿项目数量过多（>50个）时页面卡顿启用虚拟滚动，只渲染可见区域的项目卡片
删除后状态未更新删除成功后卡片仍显示立即移除DOM并重新获取列表，避免缓存不一致

6.2.3 创建项目 - 步骤一：设置项目名

触发条件：

  • 用户在首页点击"立即部署"或"创建"按钮
  • 用户通过快捷入口触发创建流程

用户场景：

  • 场景1 - 新项目创建：员工小刘需要为团队创建一个DevOps助手，输入"team-devops-bot"作为项目名
  • 场景2 - 名称冲突处理：员工尝试使用已有名称，系统提示后更换为"team-devops-bot-2026"
  • 场景3 - 快速取消：员工误触创建按钮，按ESC快速关闭弹窗

交互跳转说明：

  1. 弹出 Modal 弹窗，遮罩层透明度 50%
  2. 输入框自动聚焦，显示 placeholder"请输入项目名称"
  3. 实时校验项目名称（长度 2-50 字符，仅支持中文、英文、数字、下划线）
  4. 点击"下一步"或按 Enter 键进入步骤二

预期结果：

  • 弹窗平滑动画出现（200ms ease-out）
  • 输入框有明确的状态反馈（默认/聚焦/错误）
  • 校验失败时显示错误提示文案
  • 项目名称实时保存到本地状态

约束条件：

  • 项目名称全局唯一，重复时提示"该项目名已存在"
  • 不能为空或仅包含空白字符
  • 不能使用系统保留字（如 admin、test、api 等）
  • 弹窗支持 ESC 键关闭，点击遮罩层关闭
异常场景现象处理方式
项目名称重复输入已存在的项目名称实时校验并显示红色提示"该项目名已存在，请更换"，禁用下一步按钮
包含特殊字符输入"my bot!"等含特殊字符的名称校验失败，提示"仅支持中文、英文、数字、下划线"，并标红非法字符
网络延迟导致校验超时输入后长时间无校验反馈显示"正在校验..."，3秒后超时显示"校验失败，请重试"
输入框失焦后未保存用户输入后直接关闭弹窗提示"有未保存的更改，确定要离开吗？"确认对话框

6.2.4 创建项目 - 步骤二：配置飞书渠道

触发条件：

  • 用户成功完成步骤一（输入有效项目名）
  • 用户点击"下一步"按钮

用户场景：

  • 场景1 - 完整配置：员工小陈有飞书机器人凭证，填写完整的AppID和AppSecret
  • 场景2 - 先跳过配置：员工小马暂无凭证，选择"跳过此步骤"先创建项目
  • 场景3 - 返回修改：员工发现项目名有误，点击"返回上一步"修改

交互跳转说明：

  1. 显示头像选择器（网格展示 20+ 预设头像）
  2. 提供"机器人配置"折叠面板（默认收起）
  3. 若展开配置面板，显示 AppID 和 AppSecret 输入框
  4. 提供"跳过此步骤，稍后配置"复选框
  5. 点击"创建"按钮提交，进入创建进度页面

预期结果：

  • 默认选中第一个头像
  • 点击头像有选中状态反馈
  • 配置面板展开/收起有平滑动画
  • 表单数据验证通过后才能提交

约束条件：

  • 若选择跳过配置，项目状态标记为"待配置"
  • AppID 格式校验（以 cli_ 开头，16 位字符）
  • AppSecret 最少 32 位字符
  • 若填写了配置，必须两者都填写且格式正确
  • 提供"返回上一步"按钮，可修改项目名称
异常场景现象处理方式
AppID格式错误输入"abc123"等非标准格式校验失败，提示"AppID格式错误，应以cli_开头"
AppSecret过短输入少于32位字符校验失败，提示"AppSecret长度不足32位"
只填其中一个仅填写AppID未填AppSecret提示"请同时填写AppID和AppSecret，或选择跳过"
凭证验证失败提交后后端验证凭证无效显示错误"飞书凭证验证失败，请检查是否正确"，不关闭弹窗
头像选择卡顿头像网格加载缓慢显示骨架屏占位，加载完成后平滑过渡

6.2.5 创建进度展示

触发条件：

  • 用户点击"创建"按钮提交表单
  • 后端返回创建任务 ID

用户场景：

  • 场景1 - 正常创建：员工正常等待3步全部完成，看到成功提示
  • 场景2 - 快速跳转：步骤2完成后，员工急于配置飞书，点击步骤3直接跳转
  • 场景3 - 页面意外关闭：员工误关浏览器，重新打开后恢复进度
  • 场景4 - 长时间等待：某步骤执行时间较长，员工想了解详情

交互跳转说明：

  1. 进入创建进度页面，显示三步进度条
  2. 通过 WebSocket 实时接收进度更新
  3. 每步显示：步骤名称、状态图标、耗时
  4. 步骤 2（启动 OpenClaw）完成后，可点击跳转至步骤 3
  5. 完成后显示成功/失败弹窗

预期结果：

  • 进度条实时更新，步骤完成后打勾
  • 显示每个步骤的开始时间和耗时
  • 任意步骤失败时，显示错误信息和重试按钮
  • 成功后显示"部署完成"提示和下一步操作按钮

约束条件：

  • WebSocket 连接失败时，降级为轮询（5s 间隔）
  • 总超时时间：10 分钟，超时显示失败
  • 步骤可点击跳转仅限：步骤 2 完成后可跳至步骤 3
  • 页面刷新后，若创建中则恢复进度展示

11. 后端服务规格

11.1 编排引擎

触发条件：

  • 用户提交创建项目请求
  • 管理员执行实例操作（启动/停止/重启/删除）

用户场景：

  • 场景1 - 自动创建实例：用户点击创建后，系统自动完成虚拟机创建到OpenClaw启动的全流程
  • 场景2 - 批量操作：管理员对多个实例执行重启操作，系统并发处理但控制并发数
  • 场景3 - 失败自动清理：创建失败时，系统自动回滚并清理已创建的资源，避免资源浪费
  • 场景4 - 进度实时同步：用户在前端看到创建进度实时更新，了解当前执行步骤

约束条件：

  • 最大并发创建数：5 个
  • 虚拟机规格限制：CPU ≤ 4 核，内存 ≤ 8GB
  • 配置文件注入需加密敏感字段
  • 支持创建回滚（失败自动清理资源）
异常场景现象处理方式
云平台API限流创建请求被云平台拒绝指数退避重试，最多重试3次，仍失败则标记任务失败
安装脚本执行失败OpenClaw安装过程报错记录详细错误日志，自动清理已创建资源，通知用户失败原因
配置文件注入失败写入配置时权限不足或磁盘满重试3次，失败后标记步骤失败，保留虚拟机供人工排查
Gateway启动超时服务启动超过预期时间超时后检查进程状态，如已启动则继续，否则标记失败
WebSocket推送失败前端无法接收进度更新降级为前端轮询查询进度，不影响后端执行流程
并发超限第6个创建请求进入队列返回"系统繁忙，当前有X个任务在执行，请稍后重试"

11.2 飞书集成服务

触发条件：

  • 用户配置机器人信息
  • 管理员审批通过
  • 定时任务检查长连接状态

用户场景：

  • 场景1 - 凭证安全存储：系统加密存储用户配置的AppID/AppSecret，即使数据库泄露也无法直接读取
  • 场景2 - 自动建立连接：审批通过后，系统自动与飞书建立WebSocket长连接，无需人工干预
  • 场景3 - 消息实时转发：用户通过飞书发送消息，系统实时转发给OpenClaw处理并返回结果
  • 场景4 - 连接状态监测：系统自动监测长连接状态，断线后自动重连，保障服务稳定性

约束条件：

  • 凭证加密密钥定期轮换
  • 飞书 API 限流处理
  • 长连接心跳间隔：30s
  • 断线重试次数：5 次，间隔指数退避
异常场景现象处理方式
凭证解密失败密钥轮换后旧凭证无法解密标记凭证失效，通知用户重新配置
飞书API限流请求频率超过飞书限制队列缓冲请求，指数退避重试，记录限流日志
长连接频繁断开WebSocket连接不稳定增加心跳检测频率，缩短重试间隔，记录断线原因
消息转发超时消息处理超过1秒未响应超时后返回"处理超时"给用户，后台继续处理并异步通知结果
凭证验证失败飞书返回凭证无效标记连接状态为"待配置"，通知管理员检查凭证

11.3 监控服务

触发条件：

  • 定时任务（每 60s）
  • 实例状态变化
  • 用户手动触发检查

用户场景：

  • 场景1 - 异常自动发现：系统检测到实例异常，1分钟内自动发送飞书通知给管理员
  • 场景2 - 定期巡检：系统每60秒自动检查所有实例健康状态，生成监控报告
  • 场景3 - 告警收敛：同一实例频繁异常，系统只发送一次告警避免消息轰炸
  • 场景4 - 静默期设置：夜间维护期间，管理员设置静默期避免误告警打扰

约束条件：

  • 监控不占用过多资源（CPU < 5%）
  • 告警去重（同一问题 1 小时内只发一次）
  • 告警分级：警告/严重/致命
  • 支持告警静默期设置
异常场景现象处理方式
探测命令执行失败SSH/ping命令失败记录失败原因，标记为"探测失败"状态，继续下一轮探测
告警通知失败飞书消息发送失败重试3次，仍失败则记录告警日志，不阻塞监控流程
监控自身异常监控服务CPU过高或内存溢出自动重启监控服务，保留监控数据，发送"监控服务异常"告警
误报频繁实例实际正常但频繁告警增加判定阈值，连续3次异常才触发告警，减少误报
告警风暴大量实例同时异常导致告警风暴启用告警合并，5分钟内同类告警合并为一条消息

12. 通用功能规格

12.1 权限控制

触发条件：

  • 用户访问任何页面/接口
  • 用户执行任何操作

用户场景：

  • 场景1 - 员工权限控制：普通员工只能查看自己的项目，无法查看他人项目或访问管理后台
  • 场景2 - 管理员权限：管理员可以查看所有项目并执行管理操作
  • 场景3 - 权限变更：员工调岗后，重新登录后自动获取新的权限配置
  • 场景4 - 越权拦截：用户尝试通过URL直接访问无权限页面，被系统拦截

约束条件：

  • 支持 RBAC 模型
  • 权限粒度：页面级 + 操作级
  • 权限数据缓存时间：5 分钟
  • 敏感操作需二次认证（预留）
异常场景现象处理方式
权限数据加载失败登录后无法获取权限使用默认最低权限（普通员工），允许访问首页，其他功能提示"权限加载失败"
权限缓存过期操作时被提示无权限清除缓存重新获取权限，如仍无权限则返回403
角色权限配置错误配置文件中权限语法错误启动时校验配置文件，错误时拒绝启动并提示具体错误位置
接口未设置权限后端接口未添加权限校验代码审查检查，未设置权限的接口默认拒绝访问（白名单机制）

12.2 错误处理

触发条件：

  • 接口请求失败（4xx/5xx）
  • 网络异常
  • 业务逻辑错误

用户场景：

  • 场景1 - 网络错误恢复：用户网络短暂中断，系统自动重试请求，用户无感知
  • 场景2 - 服务器错误提示：遇到500错误，用户看到友好提示"系统繁忙"并提供重试按钮
  • 场景3 - 权限错误处理：用户尝试无权限操作，系统提示"您无权限执行此操作"并记录日志
  • 场景4 - 业务错误处理：用户输入非法参数，系统提示具体错误原因并引导修正

约束条件：

  • 错误提示文案统一规范
  • 500 错误显示"系统繁忙，请稍后重试"
  • 错误日志包含：用户、时间、操作、错误详情
  • 关键错误实时告警
异常场景现象处理方式
错误重试耗尽自动重试3次仍失败显示"操作失败，请稍后重试"，提供"联系支持"入口
错误信息泄露错误详情中包含敏感信息统一错误包装，生产环境不暴露堆栈和内部错误详情
错误提示文案缺失新类型错误无对应文案兜底显示"操作失败"，记录日志提示开发补充文案
频繁相同错误同一用户频繁触发相同错误速率限制，5分钟内相同错误只记录一次，避免日志刷屏

12.3 日志审计

触发条件：

  • 用户执行关键操作（创建、删除、配置变更等）
  • 管理员执行管理操作

用户场景：

  • 场景1 - 操作追溯：管理员发现配置异常，通过日志查询谁在什么时间修改了配置
  • 场景2 - 安全审计：安全团队定期检查日志，发现是否有越权操作或异常访问
  • 场景3 - 问题排查：项目被误删除，通过日志找到删除操作人和具体时间
  • 场景4 - 合规报告：生成季度操作日志报告，满足企业合规审计要求

约束条件：

  • 日志保留时间：90 天
  • 单条日志大小限制：10KB
  • 日志表分区存储
  • 支持日志归档到对象存储
异常场景现象处理方式
日志写入失败数据库连接失败导致日志丢失本地文件缓冲，恢复后批量写入，关键操作同步等待写入成功
日志查询超时查询90天日志耗时过长默认只查询最近7天，大范围查询需确认，提供导出异步查询
日志被篡改发现日志记录被非法修改数字签名校验，发现篡改立即告警并锁定日志功能
日志存储满磁盘空间不足无法写入新日志自动清理最旧的分区，保留关键安全日志，发送存储告警
单条日志超大操作详情超过10KB截断超长内容，保留前10KB，记录"内容已截断"标识
